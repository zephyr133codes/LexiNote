## 2. 项目背景

在英文文章阅读、大学英语四六级备考、英文演讲稿练习等学习场景中，学习者经常遇到不认识、不会发音或者难以记忆的英语单词。

目前，常见的英语词典和阅读工具虽然能够提供单词翻译、音标和发音，但在实际学习过程中仍然存在以下不便：

1. 查询单词时，需要频繁切换页面或者打开词典。
2. 查询结果通常不能直接、持久地标注在原始文章中。
3. 缺乏灵活的音标、翻译和词组注释排版方式。
4. 用户需要手动整理文章中的生词，重复劳动较多。
5. 带音标、翻译的英文演讲稿及学习资料制作过程较为繁琐。
6. 文章阅读与后续单词记忆之间缺乏连续的学习流程。

因此，本项目计划开发一款支持英语文章交互式阅读、智能词汇查询、原文持久标注、词汇整理和学习资料导出的应用程序。

## 3. 项目目标

### 3.1 总体目标

开发一款面向英语学习者的 Android 应用程序，实现英语文章导入、单词与词组查询、个性化原文标注、文档导出及词汇学习管理等功能。

通过软件减少用户在阅读过程中反复查词、添加音标、整理生词和制作学习资料所需的时间。

### 3.2 具体目标

1. 支持用户导入英文文章和 Word 文档。
2. 支持通过单击操作选择文章中的单词。
3. 支持通过长按拖动选择短语或多个连续单词。
4. 自动匹配选中单词的音标和中文释义。
5. 允许用户在原文中添加永久注释。
6. 支持选择音标、中文翻译、详细解释等注释内容。
7. 支持在单词上方、下方或后方显示注释。
8. 自动汇总文章中查询和标注过的单词。
9. 支持将文章生词批量加入个人词库。
10. 支持将带注释的文章导出为 PDF。
11. 后续扩展单词记忆和复习功能。
12. 后续研究基于上下文的智能词组识别。

## 4. 项目目标用户

### 4.1 主要用户

- 大学英语四级、六级备考学生。
- 英文 Presentation 演讲练习者。
- 有英文文章阅读需求的大学生。

### 4.2 扩展用户

- 考研英语学习者。
- 雅思、托福学习者。
- 英文论文阅读者。
- 需要整理英文资料的其他用户。

### 4.3 典型应用场景

**场景一：英文演讲稿注音**

用户导入英文演讲稿，选择不会发音的单词，自动添加音标，最后导出 PDF 打印，用于朗读与演讲练习。

**场景二：英语四六级阅读**

用户导入英语阅读文章，在阅读过程中选择生词和短语，查看中文解释，并保存原文注释。

**场景三：文章生词整理**

用户阅读完成后，系统自动汇总已查询的单词，用户可以进行批量选择，并将其添加到个人生词本。

**场景四：单词复习**

用户进入个人生词本，通过单词卡片、词义回忆等方式进行学习，并查看单词出现的原始文章和例句。

## 5. 项目功能范围

### 5.1 第一版本核心功能（V1.0）

**模块一：文章管理**

- 创建、保存和删除文章。
- 支持粘贴英文文本。
- 支持 TXT 文本导入。
- 支持 DOCX 文档导入。
- 保存文章标题、内容和创建时间。

**模块二：交互式词汇查询**

- 单击英文单词进行查询。
- 长按拖动选择词组。
- 显示单词音标和中文释义。
- 支持词形还原及基础词典匹配。
- 处理常见标点和大小写差异。

**模块三：原文注释**

- 将音标添加到选中单词附近。
- 将中文释义添加到选中单词附近。
- 支持上方、下方、后方三种注释位置。
- 支持配置注释显示内容。
- 支持删除与修改注释。
- 支持隐藏注释，仅显示原文。
- 关闭应用后保留已有注释。

**模块四：词汇统计**

- 汇总当前文章查询过的单词。
- 统计单词查询次数。
- 对重复单词去重。
- 支持查看对应原文位置。
- 支持选择多个单词。

**模块五：文档导出**

- 支持导出原始文章。
- 支持导出带音标的文章。
- 支持导出带中文翻译的文章。
- 支持导出完整注释文章。
- 支持 PDF 格式输出。
- 支持基础打印排版设置。

### 5.2 后续扩展功能（V1.5）

- 个人生词本。
- 批量添加和删除生词。
- 单词记忆卡片。
- 单词掌握状态管理。
- 基础间隔重复复习。
- 拼写纠错。
- 更完整的词形变化匹配。

### 5.3 长期扩展功能（V2.0）

- 基于上下文的词组智能识别。
- AI 词义解释和句子分析。
- 整句翻译。
- 多设备学习数据同步。
- 平板适配。
- 微信小程序版本。
- HarmonyOS 原生版本。

## 6. 初步技术方案

### 6.1 目标平台

第一版本优先开发 Android 应用。

后续根据用户需求和技术可行性考虑其他平台。

### 6.2 技术选型

| 技术模块 | 初步选型 |
|---|---|
| Android 开发 | Kotlin |
| 开发工具 | Android Studio |
| 阅读界面 | HTML、CSS、TypeScript |
| 阅读组件容器 | Android WebView |
| 本地数据库 | SQLite / Room |
| 词汇查询 | 本地英语词典数据库 |
| 文件导入 | Android 文件访问能力 |
| PDF 导出 | HTML 排版及 Android PDF / 打印能力 |
| 版本管理 | Git、GitHub |
| AI 编程辅助 | Codex |

以上方案为初步设计，需要在技术验证阶段进一步确认。

### 6.3 系统设计原则

1. 优先实现本地离线功能。
2. 原始文章和用户注释分开存储。
3. 不同功能采用模块化设计。
4. 将阅读器核心与 Android 平台功能尽可能解耦。
5. 保证用户数据的完整性和可恢复性。
6. 保持代码结构清晰，方便后续增加功能。

## 7. 项目可行性分析

### 7.1 技术可行性

Android 平台支持文件访问、本地数据库、WebView 和 PDF 输出等能力。

项目主要功能具有明确的技术实现路径。

但复杂文本选择、注释定位、自动换行和 PDF 排版需要通过独立原型进行验证。

### 7.2 经济可行性

项目计划优先使用免费的开发工具与可合法使用的开源组件。

第一版本不搭建云服务器，不要求付费 AI 接口。

词典数据需要单独检查许可证和使用条件。

### 7.3 开发可行性

项目采用单人开发模式，利用 Codex 辅助代码编写。

通过模块化设计和迭代开发降低开发复杂度。

### 7.4 运行可行性

Android 手机具备良好的文档阅读和触控交互条件，能够满足文章阅读、单词查询和词汇复习等基本使用场景。

## 9. 项目主要风险

| 风险 | 应对措施 |
|---|---|
| 富文本交互复杂 | 提前开发最小技术原型 |
| 注释排版不稳定 | 独立设计注释渲染模块 |
| Word 导入兼容性问题 | 首版优先支持正文和基础段落 |
| PDF 导出排版异常 | 提前进行分页和字体测试 |
| 词典数据不完整 | 使用合法词典数据并支持手动修改 |
| Android 开发经验不足 | 分阶段学习，使用Codex辅助 |
| 开发周期超出计划 | 明确版本范围，控制功能扩展 |

## 10. 项目验收标准

第一版本完成后，应满足以下基本要求：

1. 能够在 Android 手机上正常安装和运行。
2. 用户能够导入并阅读英文文章。
3. 用户能够准确选择单词或连续词组。
4. 系统能够查询并显示单词音标和释义。
5. 用户能够将注释保存到原文对应位置。
6. 支持切换注释内容和显示位置。
7. 关闭并重新打开软件后，注释仍然存在。
8. 能够汇总文章中查询过的生词。
9. 能够将文章导出为 PDF。
10. 软件在正常阅读操作下保持稳定。
