# V0.3.4.2 标注状态与性能基准

## 第三阶段：按视觉行分配辅助槽

ReaderParagraphLayout 取代块内 FlowRow：只组合当前可见层，每个 Text 在屏宽约束下真实测量一次；以三层最大宽度分行。ReaderLinePlan 按行计算最大音标高度、英文最大 ascent/descent、最大翻译高度，英文通过 FirstBaseline 对齐。各层在单元宽度内居中；没有上下层时高度为零，不预留空槽。点击用同一测量结果产生的矩形直接回传 token，不换算字符下标。

正文 18sp/26sp，音标和翻译 12sp/16sp；音标蓝灰、翻译墨绿，深色主题使用对应亮色。极长英文在单元内部软换行；音标和翻译最多两行后省略，完整释义仍在详情中查看。空行高度随字体缩放。

技术拆块暂保留，避免扩大懒加载架构；修复恰好在技术拆块后遇到物理换行时多生成空段的问题。技术边界仍会开始新视觉行，是已知限制。原文字符、分隔符、offset、分词缓存及持久化链路不变。

验证：本地 12 项测试通过，含四种槽位状态、基线对齐、换行/命中矩形、极长单元高度和技术边界测试。最终 testDebugUnitTest + assembleDebug + assembleDebugAndroidTest 出现 BUILD SUCCESSFUL。设备已有 Room 测试通过；新增 Compose UI 测试在 API 37 遇到现有测试基础设施 InputManager.getInstance 的 NoSuchMethodException，布局断言尚未执行。未升级依赖。

设备截图待验收：明暗主题四种层组合、字体放大/窄屏、连续标注的英文基线、长音标与长翻译、标点空白点击、快速滚动、块边界。每次测量仍需测当前可见块的 Text；未获得帧率/首帧/内存前后对照数据，不能声称已证实没有性能回退。

## 第二阶段记录：2026-11-25

优化前正文在 ArticlePreviewScreen 的 Composable 中执行 findAll().toList()、段落重分组，并使用 Column.verticalScroll 一次组合全部 FlowRow。标注原已有起点 Map，因此不是每个词线性扫描全部 annotations；问题是全文预处理和 eager 组合未隔离。

优化后 ReaderDocumentCache 只保存最近一次 articleId + 正文及分词结果，Dispatchers.Default 执行扫描。每个 token 和 block 保留原始 UTF-16 offset。CRLF/LF/CR 分隔符单独保留，空段显示明确空行。超过约 160 token 的段落在后续空白 token 结束处拆块；极端无空白字符串不会被强行切断。

ReaderBody 使用 LazyColumn，key 为 articleId:start:end。标注构成起点索引；每个可见块通过 derivedStateOf 选取自身 token 的标注，Map 相等时不发出局部变化，ReaderParagraph 复用相同 token 模型与回调。开关不参与分词缓存 key。Room Flow 与 DAO 事务未改。

真实验证：7 项本地 JUnit 测试全部通过；最终 testDebugUnitTest + assembleDebug + connectedDebugAndroidTest 在 Medium_Phone_API_37.0 模拟器执行，BUILD SUCCESSFUL in 17s。现有设备测试验证 Room 并发保存等逻辑，未验证阅读页面帧率/点击像素命中。

缓存测试中相同文章/正文读取 11 次，分词构建计数为 1；切换文章、修改正文分别增加一次。170000 字符长段落测试验证重建字符与原文完全相等、10000 次 next-word 未被切断、全部文本范围有效。此为正确性与执行次数结果，不是速度基准。

首次进入、首帧、内存峰值/GC、滚动帧时长、保存到可见延迟：优化前后均待测。请沿用下文相同设备/样本协议，CPU Profiler 查看分词线程与 Compose 测量；Layout Inspector 检查未变化段落的重组；Memory Profiler 记录峰值/GC。重点补测 CRLF/空行、相邻标注、长块边界以及开关后的滚动位置。

已知限制：人为文本块边界会成为新的视觉折行边界；原始字符串与 token offsets 不变。极长无空白串仍可能是单个大 token；本轮未引入新的省略/断词策略。尚未实现统一英文基线或最终三层布局。

## 修改前静态基准（非设备测量）

- 每次预览/编辑调用 observeAnnotations 都启动独立的 viewModelScope collector，无取消。
- 所有文章共用不带 articleId 的标注列表。
- 每次保存查询目标位置、写入，再主动读取完整标注快照；Room invalidation 同时触发 Flow 重新查询。
- 先查询后插入/更新没有事务封装。
- 全文 FlowRow、分词与文本测量仍为现有实现，本阶段没有优化。
